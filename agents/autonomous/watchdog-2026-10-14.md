# MaximusSCPI — supervision indépendante (14 octobre 2026)

## État installé

Le 14/10/2026, une fonction `maximus_agents.watchdog_tick()` et un cron Supabase (`maximus-agents-watchdog-30m`, ID initial 69, minute 07 et 37 de chaque heure, UTC) ont été installés sur le projet `ygvsddcpohsnaowofuwc`.

Le watchdog écrit dans les tables privées (RLS, aucun accès anon/authenticated) :

- `maximus_agents.watchdog_observations` : observation datée, statut de l'exécuteur, tâches en attente, incidents, résultat du crash-test strict (61 SCPI), conservation 90 jours.
- `maximus_agents.watchdog_incidents` : incidents actifs et historique agrégé. Deux codes : `AI_WORKERS_STALLED` et `SCPI_STRICT_FAILURES`.

La fonction n'appelle **aucun modèle IA** et ne prétend **pas** exécuter DATA/ANALYST/SEARCH/QA. Elle n'édite aucun indicateur SCPI, n'active aucun backfill massif et ne déclenche aucun déploiement Netlify.

## Vérification

```sql
select jobid,jobname,schedule,active
from cron.job where jobname='maximus-agents-watchdog-30m';

select observed_at,runner_state,pending_tasks,strict_pass,strict_fail
from maximus_agents.watchdog_observations
order by observed_at desc limit 10;

select incident_code,active,first_seen,last_seen,occurrences,evidence
from maximus_agents.watchdog_incidents order by incident_code;

select jobid,status,start_time,return_message
from cron.job_run_details where jobid=69
order by start_time desc limit 10;
```

Le diagnostic doit rester à `STALE` tant qu'aucun worker n'émet de heartbeat valide ; ne jamais le présenter comme une réparation autonome réussie.

## Étape manquante pour les corrections autonomes

Pour rendre les cinq agents réellement indépendants d'une automatisation ChatGPT, connecter **un exécuteur IA externe authentifié** au registre privé `maximus_agents`, capable d'utiliser le contrat `agents/autonomous/execution-contract.md`, de faire une implémentation sourcée sur branche `agents/autonomous*` ou dans Supabase, puis de requérir une QA indépendante. L'exécuteur doit :
- prendre une tâche par `claim_task` (2 claims/rôle/jour maximum, 2 tentatives/tâche) ;
- enregistrer ses preuves et ses tests via `record_execution` ;
- respecter l'interdiction d'inventer les données, de fusionner `main` ou de déclencher Netlify ;
- émettre un heartbeat **après une exécution réelle** (jamais par le watchdog) ;
- remonter les échecs visibles dans GitHub Actions ou une supervision externe.

Ne pas ajouter de facturation de modèles/API ou de secrets à GitHub sans validation des coûts et des habilitations.

## Réactivation / rollback

Pour **suspendre la surveillance uniquement** : `select cron.unschedule('maximus-agents-watchdog-30m');`

La fonction et ses journaux restent consultables ; les crons métier des bulletins, backfill et rapports annuels sont inchangés.
